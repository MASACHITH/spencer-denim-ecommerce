## Done (PR on `feature/253-bank-transfer-sri-lanka`)

- **The rule is the provider's, so checkout still names no gateway (PAY-03).** `IPaymentProvider.DomesticDeliveriesOnly`
  (default false; `BankTransferProvider` true), carried on `CheckoutPaymentMethod` by `CheckoutReader` the way
  `IsAvailableAsync` already was. `DestinationRules.PaymentMethodsFor` filters for the page and for placement, so
  the two cannot disagree; `PaymentMethodNotForDestination` is the named refusal ("Bank or online transfer is only
  available for deliveries within Sri Lanka. Choose another way to pay for delivery to United Kingdom.").
- Placement order of checks: a domestic-only method named for an overseas order → named 400 (even when it is the
  only method on); otherwise no method for the destination → 409 `NoPaymentMethod`, as for none at all.
- Storefront: a choice the new country's list no longer offers is cleared (then a single remaining method is
  auto-chosen, as before); with none offered abroad the page names the country instead of "try again later".
- Admin panel hint and three admin-guide passages say bank transfer is for Sri Lankan deliveries only.
- e2e stub mirrors the rule. PayPal is **off by default** in the stub and switched on per request with an
  `x-e2e-paypal: on` header (a shared switch would race under fullyParallel); ~40 domestic flows rely on the single
  auto-chosen method and are untouched. `intl-delivery.e2e.ts`'s overseas tests opt in.
- `InternationalCheckoutTests` moved onto `PayPalTestBase`: its overseas placements used to pay by bank transfer,
  which is now (correctly) refused — they were the 7 failures on the first run. PayPal is only offered through the
  PayPal host, hence `NewPayPalBagAsync`.
