1. **Ubuntu 26.04's default coreutils is uutils.** `install -d -o <n> -g <n>` refuses a number with no passwd/group entry, and the
   containers' users (API 1654, SQL Server 10001) have none on the host, so `install.sh` stopped at its first owned directory
   (`install: invalid group: '1654'`); `deploy.sh` had the same two lines. Fix: `owned_dir` in `lib.sh` (`install -d -m`, then
   `chown`, which takes numeric ids). New `tests/test-install-owners.sh` (22 checks; 15 mutations turn it red; red on the old code
   with the server's own message). An independent tester reviewed it and its first version was too weak, so it was rewritten.
2. **The sheet's B5 password generator made letters and digits only.** The API's staff rule needs a symbol too. `check-env.sh`
   checked only the length, the deploy went green, and the API logged `SeedingFailed` ("Passwords must have at least one non
   alphanumeric character") with no admin created. Fixed on the server by replacing the password and redeploying the same tag;
   in the repo by the generator in B5, D1 and a `check-env.sh` rule for the four kinds, with `tests/test-check-env-seed.sh`
   (17 checks; 12 go red when the rule is removed; never prints the value).
3. **`verify-public.sh` called the other project's front end "the shop".** It is an Angular app too, so a bare `<app-root` matched
   our markup fingerprint (FAIL `unknown-host-https`). Now only `ng-version` / `ng-server-context` or our headers count; mock fault
   `unknown-host-other-tenant` and a test case, red if the old rule returns. On this server an unknown host name on 443 is answered
   by the other project: that is a WARN, the intended result of skipping the catch-all (A4 #14).
4. **The nginx error-log directory and logrotate were missing from the sheet** (the templates write `error_log` there and `nginx -t`
   needs the directory). Now in B12-a.
