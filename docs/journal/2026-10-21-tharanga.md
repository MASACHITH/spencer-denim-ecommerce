**Found (would cost the next person time):** Ubuntu 26.04's default coreutils is **uutils** (`rust-coreutils` 0.8.0). Its
`install -d -o <n> -g <n>` refuses a number that has no passwd/group entry, and the containers' users (API 1654, SQL Server
10001) have none on the host. GNU `install` accepted them, so the scripts, their tests and the first tester pass (which ran on
Git Bash and a container) never saw it. `chown`/`chgrp` take numeric ids under uutils, so the fix is to create with
`install -d -m` and then `chown`: `owned_dir` in `deploy/scripts/lib.sh`, used by `install.sh` and `deploy.sh` (which had the same
two lines and would have failed at the first deploy). New `tests/test-install-owners.sh`: red on the old code with the server's own
message, green on the fix. Nothing sensitive was written by the failed run: B5 stopped because the env templates had not been
copied, before it generated a password.
