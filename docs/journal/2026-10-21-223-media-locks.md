# 2026-10-21 — #223: media delete edge cases, and #191's lock order for every catalogue media owner

Branch `fix/223-media-delete-locks`, worktree `worktrees/sd-medialock`, cut from `main` at `299a53a`. **No
migration.** Not pushed. Developer pass; the tester pass is next.

## 1. What changed

**The lock order now covers products, categories and departments** (doc 08 §5.3, rewritten). Order: the
department row (department save only), then every `media.MediaAssets` row the save will point at **by ascending
id**, each `WITH (UPDLOCK, READCOMMITTEDLOCK, ROWLOCK)`, then a re-check (not deleted, ready, public, of the slot's
kind), then the writes, all in one transaction inside the execution strategy. The media delete takes only its one
asset row.

- `Infrastructure/Media/MediaAssetRowLocks.cs` (new): `LockAndRecheckAsync` (one statement per asset, so the lock
  order is ours and not the plan's) and `SyncUsagesAsync` (rewrites an owner's usage rows, keeps rows still wanted
  so their `CreatedAtUtc` does not move, and copes with a retried attempt's still-tracked `Added` rows).
- `Application/Catalog/Admin/Abstractions/CatalogMediaClaim.cs` (new): the slots a save points at (asset, usage
  role, request field), an optional `LockDepartmentId`, an optional `UsageOwnerType`, and `Unavailable` set by
  the store. `CatalogSaveOutcome.MediaUnavailable` is new; `CatalogWriteSupport.ToResult(outcome, id, claim)` turns
  it into the existing 400 field-error shape.
- **Products**: `AddProductAsync` takes the claim and locks before the insert; the edit goes through the new
  `SaveWithMediaAsync` (transaction, lock, re-check, one `SaveChanges(false)`, commit, accept). Slots come from
  `ProductWriteRules.DesiredMediaUsages` (gallery/hover/video rows, card, hover, swatches); fields are
  `media[i].assetPublicId` / `colours[i].swatchAssetPublicId`, or `media` for a row the request did not name.
  Posters are not claimed (the delete refuses a live video's poster; the video row is locked). Usage rows are still
  written by `SyncProductMediaUsagesAsync`, now inside the locked transaction.
- **Categories**: create, edit and remove use the claim. **They now write `MediaUsages`** (`Category`/`Image`,
  `Category`/`Banner`); before #223 they wrote none, so the library would delete a category's tile. A removed
  category releases its rows (as a removed campaign does; ADM-11 has no restore).
- **Departments (ADM-11)**: the save locks its own department row first, then the hero, and writes a
  `Department`/`Hero` usage row (the owner type and role the client-asset importer already used). Without the
  department-row-first order a card save (department → asset) and a department save (asset → department update)
  could deadlock.
- **`MediaService.DeleteAsync`**:
  - Edge case 1: the lock query now returns `IsDeleted, DeletedAtUtc, DeletedByUserId`; a delete that waited for
    another delete of the same asset answers **404** (the documented already-deleted answer) instead of a second
    204 that overwrote the stamp.
  - Edge case 2: poster usage rows are removed set-based (`ExecuteDeleteAsync`, no row count), and the stamp is
    fixed (truncated to ms, `datetime2(3)`) before the first attempt. A retry after a commit attempt that finds the
    asset deleted with its own stamp answers **204**. (Chose idempotency over `verifySucceeded`: one mechanism,
    covers any retry, and is testable with an interceptor.)
  - New direct foreign-key checks: `Departments.HeroImageAssetId`, `Categories.ImageAssetId`/`BannerAssetId`, so
    departments and categories saved before #223 (no usage row) still block the delete.
- **Client-asset importer**: assessed, not changed. It discovers assets while walking the drop and uploads new ones
  on the same transaction; locking first needs a second pass. Risk accepted and written into doc 08 §5.3
  (deploy-time command, no admins active, 1205 retried, run is all-or-nothing).
- `ContentLockWorkloadTests` now asserts the department too and restores the department's usage rows in its
  clean-up.

**Not covered (outside the issue's list, raised here):** the store-logo setting (`SetStoreLogoCommandHandler`,
owner `Setting`) writes its usage row without the asset lock. Same fix family if wanted.

No frontend change: every refusal uses a field the admin forms already show errors for.

## 2. Tests

- Unit (`Catalog.Admin`): +10 handler tests (claims, fields, `MediaUnavailable` → 400, nothing saved, category
  remove releases rows, department lock + usage). Fakes model `UnusableAssetIds`.
- `Media/CatalogMediaLockRaceTests` (12, deterministic via `sys.dm_exec_requests`, no sleeps): product edit and
  product create vs delete in both orders, category, department in both orders, department-row-before-asset
  order, legacy department and legacy category (no usage row) still refused, removed category releases its picture,
  two parallel deletes → 204 then 404 with the first user's stamp.
- `Media/MediaDeleteRetryTests` (1): an interceptor throws `TimeoutException` from `TransactionCommitted` on a
  video-with-poster delete; answer is `Deleted`, usage rows gone, poster deletable.
- `Media/MediaOwnerLockWorkloadTests` (1): product, category, department, homepage item, card moving between
  departments, campaign, plus contested/refused/free deletes. Default 25 rounds; soak with
  `T223_WORKLOAD_ROUNDS`. It also counts deadlock victims (1205) with an EF command interceptor, because the
  execution strategy retries a 1205 and so it never shows as a 500. **250 rounds: 0 deadlocks, 0 × 5xx, 0
  orphans** (each saver 217 × 2xx / 33 × 400; contested delete 33 × 204 / 217 × 409; in-use delete 250 × 409;
  free delete 250 × 204). `MediaTestHost.Create` gained an optional `configureServices` for the interceptor.
- `AdminCatalogWriteShapeTests`' category clean-up now removes the category's usage rows (it leaked a `Category`
  row onto a seeded product image, which failed `MediaLifecycleTests` later in the run).
