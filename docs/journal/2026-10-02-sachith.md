**Decisions:**

- **The name lives in one compile-time constant per application**, not in `ops.Settings`. `StoreBrand`
  (`SpencerDenim.Domain.Branding`) and `BRAND` (`@spencer-denim/shared`). The settings table is described
  in doc 08 §3.8 and **is not built**; no admin screen can edit this; and the first consumer on the server
  is the *seeder*, so a seeded setting would have to be read before the row that holds it could be
  guaranteed to exist. The OpenAPI document title is wanted at startup before any database is touched, and
  the storefront is server-rendered, so a value fetched over HTTP would have to resolve before the first
  byte of the shell. A constant is the honest shape for something that is, today, part of the build. When
  ADM-22 lands this becomes the fallback for `Branding.StoreName` and no call site moves.

- **`StoreBrand` lives in Domain** because it is the only project every consumer already references
  (Api → Application → Domain, Infrastructure → Application), so nothing needed a new reference and no
  layering rule could be bent. It is the same category of thing as `AuditActions`: a vocabulary the whole
  system has to agree about.

- **`BRAND` lives in `projects/shared`** because it is the only code both front-end applications already
  import. Putting it in the storefront's `SITE_CONFIG` would have left the admin app with a second copy,
  which is the problem rather than the fix. `SITE_CONFIG` is the shape to copy when this becomes editable.

- **No identifier is renamed, and this is a decision rather than an omission.** `SpencerDenim.*`
  namespaces and assemblies, `SpencerDenim.sln`, the `spencer-denim-ecommerce` repository, the
  `@spencer-denim/shared` library, the `spencer-denim-frontend` package and the `SpencerDenim_Dev`
  database all keep their names. Renaming them touches connection strings, CI, every developer's local
  database and the remote, for nothing a shopper sees. Recorded in `docs/02` §I2 so it reads as a choice.

- **Three files are allowed to spell the name out**, each because it cannot read a constant: the two
  `index.html` shells (a static document the build does not run TypeScript through) and
  `Directory.Build.props` (MSBuild cannot read a C# const). Both shells' titles are replaced by every
  route anyway, during SSR as well as in the browser.

- **An already-seeded database keeps its old SEO titles, and that is correct.** `CatalogReferenceDataSeeder`
  and `HomeContentSeeder` insert only missing rows and never overwrite an edit an admin may have made, so
  seed-data changes reach **fresh databases only**. A migration that rewrote `SeoTitle` would rewrite
  whatever the client has since typed there — exactly what those seeders are careful not to do. So the
  README carries a one-off `UPDATE` per environment, guarded by `SeoTitle LIKE '%| Spencer Denim'`, which
  by construction cannot touch a title somebody has rewritten. The demo placeholder *images* carry the
  caption in their pixels and `DemoMediaPlaceholderGenerator` skips assets whose files are already on the
  volume, so those need the files deleted and the generator re-run; that is development and staging only.

- **The client progress page's `client` field stays "Spencer Denim Industries Pvt Ltd".** It renders as
  "Prepared by TU2SL for …", which is a statement about the company that commissioned the work, not about
  the shop. The page's title, heading and meta description are now Colombo Wardrobe.

- **The style tile (`design/style-tile/`) and the two `docs/guides/*.html` are left alone.** They are dated
  documents already issued for review ("Style tile, draft 1"; "DEV-GUIDE-01 v1.1, 17 September 2026").
  Editing them in place would falsify the record of what the client saw. If the owner wants the style tile
  to show the new wordmark, that is a draft 2.

**Worth writing down, because it is the lesson of the round:**

- **The first sweep was a `grep` for `Spencer Denim`, and the one thing it could not see was the same
  string with the space escaped.** `otpauth://totp/Spencer%20Denim%20Admin:` was asserted in three test
  files; two Angular specs and one integration test, which is how it surfaced — as a red integration test
  after everything else was green. The guard now sweeps the plain, percent-encoded and hyphenated
  spellings, derived from the constant, and its own doc comment says why.

- **`ClientAssetImporter` was already hard-coding "Colombo Wardrobe"** in three alt texts on `main` —
  W1-13 wrote them against the client's logo artwork. So the brand name had *already* started being
  written out in a second place before anybody decided it was the brand name, which is the exact failure
  this task's guard exists to prevent. The guard found all three on its first run.

- **A comment that quotes a brand-bearing string is a copy of it.** Two comments in `listing-page.ts` and
  `product-page.ts` illustrated the double-brand bug by quoting `"Women's clothing | Spencer Denim"`.
  They are paraphrased now rather than exempted: sweeping comments as well is what keeps them from going
  stale at the next rename, and the paraphrase reads no worse.

- **The guard has a second assertion that is easy to leave out: the exemption list must rot loudly.** If
  one of the three allowed files stops containing the name, the entry is dead and the sweep is weaker than
  it reads. Both directions are proven: a hard-coded literal in `site-header.ts` fails naming the line, and
  blanking the admin shell's title fails naming the stale exemption.

- **A golden QR matrix refused the rename, and it was right to.**
  `qr-code.spec.ts` encodes an `otpauth://` URI and asserts a fingerprint **recorded from zxing-cpp
  reading that exact string back**. Renaming the fixture made the test red, and the only two ways to make
  it green were to re-run an independent decoder or to let the encoder under test produce its own
  expectation — the second of which turns the assertion into a tautology. The fixture is reverted to the
  string the fingerprint was recorded against, with a comment saying so. The subject there is `encodeQr`,
  not the brand, and the *real* issuer is covered end to end by `AdminTwoFactorEndpointTests`.

- **The guard itself was flaky for about an hour, and the failure mode is worth the warning.** A full
  `dotnet test` that happened to run while Playwright was in flight swept
  `src/frontend/test-results` — git-ignored, written by another tool, carrying the test titles — and
  reported a hard-coded brand name in a file no human wrote. It passed on the next run. A convention test
  whose colour depends on what another process left on disk is worse than none, because the next red build
  gets waved through. The walk now prunes generated directories by name instead of filtering their files
  out afterwards, so it never even opens one; proven by dropping a poisoned `report.json` into
  `test-results` and watching the guard stay green.

**Tester's round (passed, eight follow-ups), and the two that were defects rather than polish:**

- **The README's `UPDATE` failed under the project's own documented tooling and reported success.**
  `catalog.Categories` carries a filtered index, so SQL Server refuses any `UPDATE` on it unless
  `QUOTED_IDENTIFIER` is on — and `sqlcmd` defaults it **off**, which is the pattern this README uses
  everywhere else. Reproduced here from first principles on a throwaway table rather than taken on trust:
  `Msg 1934`, **nothing applied, exit code 0**. Anyone following the documented pattern would have read
  "done" and changed nothing. `SET QUOTED_IDENTIFIER ON;` is now the first line of the block, with
  `sqlcmd -I -b` named (`-b` is what turns a SQL error into a non-zero exit). The `BEGIN TRAN` did its job:
  nothing was half-applied.

- **The CI smoke check's new comment claimed something false.** It said the marker proves the header
  wordmark; delete the whole `<header>` and **14** of 15 occurrences survive, so it passed with no wordmark
  at all. Rather than drop the claim I made it true: the check now matches
  `site-header__wordmark"[^>]*>[[:space:]]*Colombo Wardrobe` with bash's `=~` (no pipe, for the same
  pipefail reason the step's older comment gives). The closing quote after the class name is what keeps it
  off the inlined `<style>`, where the same string appears a dozen times as a selector. Verified against
  live SSR output both ways, and the YAML round-trip checked so the brackets survive it.

- **Two things I got wrong in prose and one in the sweep.** The README said "a title an admin has rewritten
  does not end in the old suffix, so it is not touched" — measured, `'Ladies frocks | Spencer Denim'` **was**
  rewritten. The behaviour is right (it keeps their words and fixes the brand); the sentence was not, and
  now says *suffix*. The check `SELECT` is widened to `'%Spencer Denim%'` so a trailing space or a
  non-suffix occurrence is **visible** even though the `UPDATE` stays suffix-only; "nothing else needs
  touching" is now scoped to what the seeders write rather than reading as a guarantee about what an admin
  has typed.

- **The guard missed `.svg` and `.webmanifest`, which is exactly where the name goes next.** An SVG
  `<title>` is the accessible name of a logo, and the client's logo artwork is in the media library waiting
  to be wired in. Both extensions added, plus `.js`, plus `tools/`, `client-progress/` and the repository
  root. `client-progress/` turned out to have a genuine single place of its own — `progress-data.js`, which
  `app.js` writes into the document title and the heading — so two files there are exempted with that
  reason, verified by reading `app.js` rather than assuming, and the stylesheet comment simply stopped
  naming the shop.

- **Widening the sweep immediately caught a bug in the widening.** The new repository-root loop yielded
  files *before* the extension filter, so the sweep read `README.md`, `MEMORY.md` and `TASKS.md` — which
  spell the name out in prose, correctly — and reported sixteen offenders. Loudly wrong rather than quietly
  wrong, but the filter is one question and now lives in one place (`IsSwept`). It also caught my own new
  comment in `login-page.ts` naming the shop, which is the rule working as intended on its author.

- **The pruning is blunt and now says so.** It matches directory *basenames* at any depth, so a real source
  folder called `dist` or `coverage` would vanish from the sweep silently — green, not red. Nothing is named
  that today; the comment tells the next person to narrow it to paths rather than trust the names.

- **The admin sign-in heading repeated the header bar and wrapped at all eight breakpoints**, not just 320.
  The `h1` is "Sign in" now and the header bar keeps the name — which removes the duplication at the same
  time. Measured one line at 320/375/390/768/1024/1280/1440/1920, no overflow.

- **The pre-rename documents keep their words and gain a date.** The style tile and the two developer
  guides now carry "the shop was renamed Colombo Wardrobe on 2026-10-02; this document predates that and is
  left as it was issued" — additive, in the masthead meta list and the document-control lines where their
  version and date already are, so the record of what the client saw stays true without a reader concluding
  the rename missed them. `docs/02` §I2 also now states that `sd_` cookies and claims, the `sd_app` /
  `sd_migrator` logins and the `sd-` / `sda-` selector prefixes are the same decision as `SpencerDenim.*`,
