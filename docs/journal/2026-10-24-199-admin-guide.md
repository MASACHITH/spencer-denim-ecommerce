Branch `feature/199-admin-user-guide`, worktree `worktrees/sd-guide`, cut from `main` at `543cb63`. **No backend

## 1. What was built

**A page at `/guide` ("User guide") in the admin app**, linked from a new **Help** group in the sidebar and from
the dashboard's section list. Open to every signed-in staff member (no permission: it is documentation).

- 47 sections (about 2,900 lines of content) in 10 groups: Start here · Access and security · Photos and video · Catalogue · Orders and delivery
  · Marketing and customers · Shop content · Reports · Settings and records · Help.
- Search (every word must match), a contents list that follows the search, deep links (`/guide#photo-sizes`),
  print / save as PDF, tables that scroll inside themselves at 320 px with the first column pinned.
- **The guide is data, not markup**: `pages/guide/content/*.ts` (one file per topic), one renderer
  (`guide-section.ts`), a tiny inline markup parser that never produces HTML (`guide-text.ts`). A new section is a
  new object, not a new template. Content reaches the page through the `GUIDE_CONTENT` token so the page's own
  tests draw three sections instead of thirty-eight.
- `styles.css` gained a small `@media print` rule that hides the sidebar, header and alert banner **for every
  page**. The invoice page prints with it too; before, it printed with the navigation column.

**`guide-content.spec.ts` is the part worth keeping.** It fails the build if: an anchor id repeats, a link goes
to a screen or a section that does not exist, a table loses a cell, a block is empty, a character is
mis-encoded, or **an admin route exists that the guide does not link to** (so a new screen cannot ship
undocumented; add the route to the guide, or to `NOT_LINKED` in the spec with a reason).

## 2. How the words were checked

Five read-only researchers (media, content, catalogue, sales, security/settings) wrote sourced fact sheets from
the **code**, not the docs. Then **three independent testers** re-checked every claim against source without
reading the fact sheets: **1,009 claims, 940 correct, 18 wrong, 37 misleading** (the rest advice that cannot be
checked in code). Every finding was fixed. Findings that mattered:

- `Orders.Refund`, the "return items to stock" tick-box, and a Refund button **do not exist**; the guide says
  refunds are manual (a first draft of the catalogue section had invented the tick-box).
- Overseas delivery is **seeded ON** with placeholder fees (Rs. 6,500 to 12,500); the first draft never said so.
- Only an Email-account change emails Super Admins; bank / PayPal / payment-method changes raise the banner only.
- The Settings screen shows no visible "Saved" message (all confirmations are screen-reader-only).
- The phone-number order search does not ignore spaces (the Customers search does).

  One copy, so it cannot drift. If a markdown copy is wanted, generate it from the content files.
- Recommended **pixel sizes are derived**, not enforced: the system accepts any size up to 60 MP and the shop
  crops with CSS. The guide says which statements are rules and which are advice.

- Process lesson: a screenshot taken straight after a deep-link load came back blank because the page was
  smooth-scrolling a long way; deep links now jump instantly.

## 5. Colours and links (owner's request, 2026-10-24)

The guide was grey and its links were black. Now: a blue head; one colour per group of sections (`GUIDE_GROUP_HUE`,
from the admin's chart palette) used on the contents list (group heading with a colour square, a rail down the
side, links in the group colour, the last section jumped to marked as current with `aria-current="location"`) and on
every section card (a stripe, a coloured group label, coloured numbered steps and bullets, tinted table headings).
Callouts are blue (Note), green (Tip) and amber (Be careful). Links are blue, bold and underlined, with an arrow that
says where they go (right: another screen; down: another place in the guide); the "Open:" buttons are blue.
Contrast was measured, not guessed: group text is 62% colour mixed with the page text colour (5.2:1 or more on every
tint, all nine colours), white on a fill is 4.7:1 or more, links are 6.7:1. axe reports nothing on the whole guide.
