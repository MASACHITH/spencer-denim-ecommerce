   `shared && storefront && admin` and stops at the first failing project. That hid the real compile error in the admin specs.

2. **The fix is more than a type error.** The endpoint replaces every field on every save, so sending nulls to please the compiler
   would have cleared a country's Express overrides each time it was blocked or reopened. The page now passes them through; a test pins it.
3. **PayPal is two switches, and the run sheet named one.** Credentials, webhook ID and a fresh rate (Settings, Payments) make PayPal
   *ready*; the provider row is seeded **off** and nothing on an existing database turns it on, so a Super Admin must also tick it in
   Settings, Payment methods. The tick stays disabled until the first is complete. docs/16 needs a line saying so (not edited here).
4. **PayPal's Webhooks Simulator is not where the webhook is made.** Apps & Credentials, the sandbox app, Webhooks, Add Webhook,
   with the full `/api/payments/paypal/webhook` URL and the six `PAYMENT.CAPTURE.*` events. The simulator's mock events cannot be verified.
